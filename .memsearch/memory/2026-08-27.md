Invoke `/skill:speckit-tdd-run` with **`all`** (the default). It drives every

blocking escape hatch, or the list is empty.

requirements). If one fires, stop and report it honestly rather than forcing ahead —

and ticked the behavior-marked tasks, so `implement` should only touch the unmarked

> Note: `implement` may have a `before_implement` hook that re-invokes
> `/skill:speckit-tdd-run all`. That is harmless here — every behavior is already
> `DONE`, so the re-run reports nothing pending and proceeds to the rest.

## Step 6 — audit: verify, then re-cycle until green

Invoke `/skill:speckit-tdd-verify`. It audits the feature's TDD discipline and test
strength from cold context (test-first evidence, smells, mutants, acceptance-criteria
coverage) and writes `FEATURE_DIR/tdd/verification.md` with a verdict:

- `PASS` / `PASS_WITH_GAPS` → the audit sub-cycle is done. Proceed to the final report.
- `FAIL` → the verdict names blocking findings and, unless `--no-tasks`, a `## Phase N:
  TDD remediation` section is appended to `tasks.md` with one task per finding.
- `BLOCKED` → an audit precondition is missing (e.g. no profile). Stop and report;
  this is not something the loop can fix.

1. Run the remediation tasks as behaviors: invoke `/skill:speckit-tdd-run` (it picks up

2. Invoke `/skill:speckit-implement` for any non-behavior remediation tasks.
3. Re-run `/skill:speckit-tdd-verify`.

Repeat this remediation sub-cycle. **Cap it** to avoid infinite loops: stop after 3
remediation passes, or earlier if the verdict stops improving, or on `BLOCKED`, or if
the user asks. Each pass, report the verdict and the top findings so progress is
visible.
